Chapter 1: Introduction

1.1 Purpose of the Report

This project report is formally submitted as an essential academic requirement for the course Mobile Application Development (MCA-20-43), bearing 2.5 credits in the 4th semester of the Master of Computer Applications (MCA) programme at the Centre for Distance and Online Education (CDOE), Kurukshetra University, Kurukshetra.

The principal objective of this document is to furnish an exhaustive analytical record of the software engineering processes, technical methodologies, design patterns, and deployment strategies applied during the development of ShopEasy. ShopEasy represents a full-stack, enterprise-grade e-commerce application capable of running simultaneously as a native mobile app on Android/iOS via Expo SDK 57 and as an adaptive Web application deployed across cloud edge networks.

1.2 Objectives of the Project Report

The core objectives undertaken and achieved during the project report are:

  • Cross-Platform Mobile Architecture: Develop a unified codebase using React Native and Expo SDK 57 that eliminates mobile-web fragmentation.
  • Dynamic Remote API Hydration: Integrate the Platzi Fake Store Cloud REST API to fetch live catalog products and multi-level categories dynamically without requiring heavy local database seeding.
  • Fault-Tolerant Data Sanitization: Implement defensive parsers to sanitize stringified JSON arrays and malformed remote image URLs.
  • Offline-First State Storage: Architect reactive Context providers for Cart and Wishlist management with persistence to device AsyncStorage.
  • Responsive Viewport Computation: Build dynamic grid layouts utilizing useWindowDimensions that automatically calculate column densities (2 to 4 columns) across mobile and desktop displays.
  • Cloud Edge Deployment: Configure automated CI/CD deployment on Vercel with single-page application (SPA) routing rewrites.

2.2 Projects and Assignments: "ShopEasy" Platform

2.2.1 Problem Definition & Existing Limitations

Conventional mobile shopping apps often impose strict authentication walls immediately upon startup, alienating potential buyers. Furthermore, multi-platform applications typically suffer from fragmented codebases where web and native mobile interfaces are written separately, doubling maintenance costs. ShopEasy was designed to address these pain points through a guest-first browsing flow and a single responsive React Native codebase.

2.2.2 Dynamic API Integration & Sanitization Pipeline

Product data is consumed dynamically from the Platzi Cloud Store API. Because third-party API payloads occasionally contain malformed brackets or stringified arrays, a defensive parsing function cleanImageUrl was engineered: 

export const cleanImageUrl = (url) => {
  if (!url || typeof url !== 'string') {
    return 'https://images.unsplash.com/photo-1523275335684-37898b6baf30?w=600';
  }
  let cleaned = url.trim();
  if (cleaned.startsWith('[') || cleaned.startsWith('"')) {
    try {
      const parsed = JSON.parse(cleaned);
      if (Array.isArray(parsed) && parsed.length > 0) cleaned = String(parsed[0]);
    } catch (e) {
      cleaned = cleaned.replace(/^[\["'\s]+|[\]"'\s]+$/g, '');
    }
  }
  cleaned = cleaned.replace(/^["']+|["']+$/g, '').replace(/\\"/g, '');
  return cleaned.startsWith('http') ? cleaned : 'https://images.unsplash.com/photo-1523275335684-37898b6baf30?w=600';
};

2.2.3 Client-Side State Persistence Engine

Shopping cart items and saved wishlist products are stored reactively via React Context and backed by @react-native-async-storage/async-storage. When users modify item quantities, state is updated optimistically in memory while an asynchronous write persists the JSON collection to disk under @shopeasy_cart.

Chapter 3: Learning Experience

3.1 Challenges Faced and Problem Resolutions

Challenge 1: Runtime Error - Missing Hook Import

Issue: Invoking the Search screen triggered an abrupt crash with the error: Property 'useWindowDimensions' doesn't exist at SearchScreen.js (111:21).
Diagnosis: The hook was invoked to dynamically compute the number of columns in the product grid, but had not been imported from react-native.
Solution: Added useWindowDimensions to the import statement and guarded columnWrapperStyle with numColumns > 1 ? styles.columnWrapper : undefined.

Challenge 2: Monorepo Cloud Deployment HTTP 404

Issue: Connecting the Git repository to Vercel produced a blank 404: NOT_FOUND screen.
Diagnosis: Vercel's build container defaulted to the root folder, which contained subfolders (backend/ and mobile/) but no root index.html.
Solution: Generated root and subfolder vercel.json deployment manifests directing the build engine to run npx expo export --platform web inside mobile/ and rewrite all routes to /index.html.

1. App Navigation Entrypoint (mobile/src/navigation/AppNavigator.js)

import React from 'react';
import { View, ActivityIndicator } from 'react-native';
import { useAuth } from '../hooks/useAuth';
import MainNavigator from './MainNavigator';

const AppNavigator = () => {
  const { isLoading } = useAuth();

  if (isLoading) {
    return (
      <View style={{ flex: 1, justifyContent: 'center', alignItems: 'center' }}>
        <ActivityIndicator size="large" />
      </View>
    );
  }

  // Opens directly to Home store page on app launch
  return <MainNavigator />;
};

export default AppNavigator;

2. Search Screen with Dynamic Columns (mobile/src/screens/products/SearchScreen.js)

import React, { useState } from 'react';
import { View, FlatList, SafeAreaView, useWindowDimensions } from 'react-native';
import ProductCard from '../../components/ProductCard';

const SearchScreen = ({ navigation }) => {
  const [products, setProducts] = useState([]);
  const { width } = useWindowDimensions();
  const numColumns = width > 1050 ? 4 : width > 680 ? 3 : 2;

  return (
    <SafeAreaView style={{ flex: 1 }}>
      <FlatList
        key={`search-grid-${numColumns}`}
        data={products}
        keyExtractor={(item) => item._id}
        numColumns={numColumns}
        columnWrapperStyle={numColumns > 1 ? { justifyContent: 'space-between' } : undefined}
        renderItem={({ item }) => (
          <ProductCard product={item} onPress={(p) => navigation.navigate('ProductDetails', { productId: p._id })} />
        )}
      />
    </SafeAreaView>
  );
};

export default SearchScreen;
